業務自動化の、その前に

資料も一緒に、
スキルへ。

Gemで使ってきた指示と参考資料を、次の仕事へ。
資料を整え、まとめて登録し、仕事の結果まで確かめる。

公開・情報確認：2026年10月20日 ／ 紙面の情報基準日：2026年10月19日

４工程を読む ↓移行チェックリストへ

連載記事「業務自動化の、その前に　資料も一緒に、スキルへ」の実践編です。GeminiのGemを手動でスキルに作り直す場合を中心に、紙面で伝えきれなかった資料の変換・登録・更新の要点をまとめました。すでに移行したスキルの資料を更新する際にも使えます。

持ち運ぶ単位は「指示＋参考資料」

手動で資料を追加・更新するときは、SKILL.mdと必要な資料を一式にして置き換えます。登録できた後は、新しい会話で実際の依頼を試しましょう。［1］

このページでできること
  1. 資料に合った変換形式を選ぶ
  2. ４工程で指示と資料を引き継ぐ
  3. 変換後の資料名を指示に反映する
  4. 新しい会話で動作を確かめる
  5. チェックリストと記録用紙を使う
  6. つまずいたとき・資料を更新するとき
  7. 公式情報と更新履歴

PREPARE

01　資料に合った形式へ変換する

スキルへのアップロードでは、PDF・画像・テキスト・CSVなどが使えますが、.doc・.docx・.xlsxは対象外と案内されています。Gemで使えた資料も、そのまま登録できるとは限りません。［1］

元の資料形式を選ぶ目安変換後に見るところ
Wordの手引き・見本図表や配置も伝えるならPDF。文章中心ならTXT・Markdownも選択肢。見出し・注記・表の欠落、文字の読みやすさ。画像だけのPDFになっていないか。
Excelの一覧・集計表見た目と集計結果を示すならPDF。行と列のデータを渡すならCSV。PDFの印刷範囲、改ページ、文字切れ。CSVの列名、文字化け、先頭のゼロ。
Notebookに登録した資料必要な元資料を用意し、PDF・テキストなどの対応形式に整える。必要な資料と版がそろっているか。Notebookへのリンクだけで済ませていないか。

この表の形式の選び方と確認項目は、本ページの実務上の提案です。PDF化しても表計算の数式・マクロは引き継げず、CSVには通常、選んだシートの値を保存します。複数シートが必要なら、それぞれを保存して資料一覧に記録します。

「現在の対応」と「今後の予定」を分ける

Googleは、Driveからのファイル追加とGemini Notebookのノートブック追加を今後提供すると案内しています。具体的な提供日は記載されていません。また、これはWord・Excel形式の直接登録を個別に約束した案内ではありません。［2］

元資料を取り出して登録する方法では、原本の改訂は自動反映されません。更新時にはスキル側の資料も差し替えます。

MIGRATE

02　指示と資料を引き継ぐ４工程

以下はパソコンのGeminiウェブアプリを使う手順です。公式の移行案内では「設定」→「スキル」、作成・管理ヘルプでは「カスタマイズ」→「スキル」と入口の表記が異なります。表示されている画面から「スキル」を開いてください。［2］［1］

  1. 1保存する指示と元資料
  2. 2手動で作る名前・説明・指示
  3. 3一式にするSKILL.md＋資料
  4. 4置き換えるまとめて登録
1

Gemの内容を保存する

対象のGemの編集画面から、名前・説明・指示をテキストで保存します。「知識」にあるファイルを開き、ダウンロードします。Drive上の文書などは元の保存先から、必要な形式で書き出します。

元ファイルと変換後のファイルを分けて保管し、版や更新日を記録しておきます。いつもの依頼文と、うまくできた出力も一つ残すと、移行後の比較に使えます。

2

指示を引き継いだスキルを手動で作成する

「スキル」の「手動で作成」を選び、保存した名前・説明・指示を転記して作成します。この段階では、参考資料の登録はまだ終わっていません。

スキル名は作成時に形式が整えられます。次の工程では、元のGemの表示名ではなく、作成されたスキル名を確認してください。

3

ダウンロードして、指示と資料をまとめる

作成したスキルの「…」メニューから「ダウンロード」を選び、ZIPを展開します。取り出したSKILL.mdと、変換済みの参考資料を、置き換えるスキルと同名のフォルダーにまとめます。

SKILL.mdはフォルダーの直下に置きます。ZIPの展開で同名フォルダーが二重になった場合は、中身を確認してください。既存スキルを更新するときは、今後も使う資料を一緒に残します。

4

スキルを置き換え、保存する

同じスキルの「…」→「スキルを置き換える」から、準備したフォルダーを選び、アップロードして保存します。管理ヘルプではZIPのアップロードも案内されています。ZIPにする場合も、メインフォルダーにSKILL.mdがある構成を確認しましょう。

アップロードの上限は合計100 MBです。SKILL.md内のスキル名は小文字・ハイフン区切りとされているため、ダウンロードした名前を基準にそろえます。［1］

４工程の基本手順はGoogleの公式移行案内［2］、アップロードと更新の要件は管理ヘルプ［1］に基づきます。保管方法と構成例は本ページで補足しました。

CONNECT

03　指示の中の資料名も直す

資料を変換しても、指示が古いファイル名を指していれば参照先が食い違います。執筆手引き.docxをwriting-guide.pdfに変えたなら、指示の中の名前も合わせます。

指示に加える例

以下は本ページの記述例です。実際の資料名・用途に合わせて直してください。

原稿の表記を整えるときは、次の参考資料を使ってください。
・writing-guide.pdf：見出し、文体、原稿の構成
・terminology.csv：用語と統一表記

資料に根拠がない内容は補わず、「要確認」としてください。
修正箇所と、参照した資料名・見出しまたは該当行を示してください。
元の原稿にある日時、人数、固有名詞は、根拠なく変更しないでください。

資料の役割を一行ずつ添えると、何をどの資料で判断するのかを確認しやすくなります。回答に書かれた参照箇所も、実際の資料と照合します。

VERIFY

04　新しい会話で、普段の仕事を試す

保存後は新しい会話を開き、/（更新後の画面では@）から対象スキルを選びます。スキルの自動選択だけに任せず、まず指定して試します。［1］ 元のGemで使った依頼文と入力を使い、次の３点を見比べましょう。

資料

必要な根拠を拾えるか

特定の用語や規則を使わせ、参照先が実在するか確かめる。

形式

欲しい形で出るか

見出し・項目順・文字数など、普段の成果物と比べる。

限界

不明を不明と言えるか

資料にない条件も尋ね、推測で埋めていないか確かめる。

試運転の依頼文

このスキルの参考資料を使って、次の原稿を点検してください。
1. 表記の修正案と、参照した資料名・該当箇所を示す。
2. 「見出し案／修正案／要確認」の順で出力する。
3. 資料にないことは推測せず、「要確認」に分ける。
4. 日時・人数・固有名詞は、根拠なく変更しない。

【原稿】
ここに、移行前にも使った確認用原稿を貼り付ける。

修正したら、また新しい会話で同じ依頼を試します。資料に書かれた事実・数値・根拠を確認した上で、以前の出力にどこまで近づいたかを判断します。上記の試し方と依頼文は、本ページの実践例です。

MAINTAIN

06　つまずいたとき・更新するとき

アップロードできない

まずSKILL.mdの場所、フォルダーとスキルの名前、非対応形式の混入、合計100 MBの上限を確認します。不要な隠しファイルも取り除きます。［1］

資料を使っていないように見える

新しい会話でスキルを明示し、資料内の特定の項目を質問します。資料名・参照箇所を答えさせ、原本と照合します。ファイル名の不一致、スキャンの文字、表の欠落も見直してください。

資料を改訂した

手元の元資料を更新し、必要なら再変換します。使い続ける資料とSKILL.mdをそろえて、スキル全体を再アップロードします。変更した資料だけの登録で済ませず、登録後に新しい会話で改訂箇所を試しましょう。［1］

自動移行を待つ場合も、何かする必要がある？

GoogleはGemsと対応する添付ファイルの自動移行を案内していますが、すべての形式・機能を同じまま使えるという意味ではありません。元の指示と資料を残し、移行後に普段の依頼を試す準備をしておきます。［2］

スキルに移せば、Gemの機能も全部使える？

CanvasやDeep Researchなどは、現時点ではスキルに対応していないと案内されています。参考資料を移す作業と、以前の機能を再現できるかの確認は分けて行います。［2］
