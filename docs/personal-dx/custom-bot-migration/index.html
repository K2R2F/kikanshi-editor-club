紙面の「11月17日」との関係

紙面では個人アカウントの移行開始を11月17日と記載している。一方、今回確認したGoogleの一般向け移行案内は「2026年11月」と月単位の記載であり、このページではその範囲を示した。実際に使っているアカウント内の通知で、適用日を確認してほしい。

GPTsの終了対象は、利用者のプランだけでなく、そのGPTを作成したアカウントやワークスペースにも左右される。また、新規作成の停止と、既存GPTの実行停止は別の変更だ。日程は各アカウントへの案内を優先して確認する。［3］

Gems・GPTsそれぞれの移行手順

Gems：自動移行を待つか、先に作り直す

Googleは、Gemsと対応する添付ファイルを自動でスキルへ移すと案内している。先に試したい場合は、元のGemの名前・説明・指示文を、設定の「スキル」から手動で作成したスキルに移せる。［2］

  1. 元のGemから指示文と知識ファイルを保存する。
  2. 「設定」→「スキル」→「手動で作成」で、名前・説明・指示文を登録する。
  3. ファイルも含める場合は、作成したスキルをダウンロードし、取り出したSKILL.mdと参考資料を、スキル名と同じ名前のフォルダーにまとめる。
  4. 「スキルを置き換える」から、そのフォルダーをアップロードする。

手動で組み直しても、非対応の機能が使えるようになるわけではない。Canvas、Deep Research、動画・音楽生成、ガイド付き学習などは、現時点でスキルに対応していない。GitHubファイルも非対応とされている。元の仕事に必要な機能かどうかを確かめ、必要なら別の工程に分けて試す。共有やDrive等からの資料追加も、利用できる状態か確認したい。［2］

GPTs：移行操作を行い、プラグインを試す

  1. 必要な下書き・変更を保存し、移行対象となる最新の公開済み版へ反映する。ここでいう公開は、不特定多数への共有を意味しない。
  2. 「My GPTs」で対象を選び、「Migrate to plugin」から移行する。
  3. 指示文・参考資料・接続済みアプリを確認し、プラグインをインストールして試す。
  4. 共同利用する場合は、移行後の共有設定と、利用者側のアクセス・インストールを確かめる。

移行後のプラグインは非公開で作られる。元の共有設定や指定モデル、未公開の編集内容はそのまま引き継がれない。元のGPTは移行後に読み取り専用になるため、その後の変更はプラグイン側で行う。［4］

Custom Actionsによる独自の外部接続は移行されない。既存アプリで代替できるかを調べ、必要ならMCPによる接続を別途構築する。MCPはAIと外部の道具・情報をつなぐ仕組みであり、導入するだけで従来の動作が再現されるわけではない。［3］

移行後、指示と資料をどう直すか

その場で出力を直しても、次の会話で同じ直しが反映されるとは限らない。繰り返し使うルールを変えたいときは、保存済みのスキル・プラグインの指示を更新することを明示する。

ChatGPT

「Plugins」から対象を開き、「Edit Plugin」を選ぶ。開いた編集用の会話で変更を依頼し、指示と資料を確認して更新を完了する。編集権限やPlugin Creatorの利用可否によって表示は異なる。［1］

Gemini

「設定」→「スキル」で対象を開く。説明・指示を直接編集するか、「その他」→「Geminiで編集」を選び、変更後に保存する。手動で参考ファイルを更新する際は、ファイルを含むスキル全体の再アップロードが必要になる。［5］

依頼には、実際の出力、期待する見本、変更点、維持する点を添える。以下は議事録用に作った依頼例で、対象名などを置き換えて使える。

指示を修正する依頼例
「〇〇」の保存済みの指示を更新してください。
添付の出力では、提案が決定事項に入っています。
見本を参考に、決定事項・継続協議・対応事項を分けてください。
資料に根拠がない担当者や期限は補わず、「要確認」としてください。
見出しの順番と文体は維持してください。
変更した指示と、同じ入力による出力例を示してください。

資料を差し替える場合は、旧版を特定する。新しい資料を追加するだけでは、新旧両方が参照候補になることがある。

参考資料を差し替える依頼例
「〇〇」の参考資料「用字用語集・旧版」を、添付の改訂版に置き換えてください。
今後は改訂版を参照するよう、保存済みの指示も確認してください。
他の参考資料と出力形式は維持し、変更箇所を示してください。

上の依頼文は、本ページで作成した実務用の例。更新手順は各社の公式案内を参照。画面の名称や提供範囲は変更されることがある。

Geminiでは、通常チャットで使うスキルと、Sparkのタスク・スケジュールの利用条件を分けて考える。公式案内では、通常チャットのスキルはGoogle AIの有料契約なしでも利用できるとされている。［5］

試運転で確かめること

更新を終えたら、新しい会話で、保存しておいた依頼文と同じ資料を渡す。ChatGPTでは@、Geminiでは/または更新後の@から対象を選択できる。自動選択も使う場合は、対象名を指定しない依頼でも確認する。［4］［5］

機関紙・議事録の仕事なら、次の観点で比較すると違いを見つけやすい。

観点確かめること
形式必要な見出し・項目・順番・文字数が保たれているか。
内容重要な発言や要点が欠けていないか。提案が決定に変わっていないか。
根拠指定した資料の版を使っているか。資料にない内容を補っていないか。
機能必要なファイルを開き、所定の成果物を作れるか。外部接続も動くか。
不明点担当者や期限が不明な例でも、勝手に埋めず、確認事項として残せるか。

一度うまくできたことだけで判断せず、普段の例に加え、情報が足りない例も試したい。調整した箇所と、引き続き保ちたい箇所の両方を確かめる。

元の指示文から組み直す場合

移行した指示がうまく働かないときは、元のカスタムプロンプトと見本をもとに、新しいスキルとして作り直す方法もある。まず「使う場面」「渡す資料」「作業手順」「出力形式」「不明な場合の扱い」を整理して、AIと相談する。

例えば、議事録作成なら「文字起こしを整理する」「議事内容を分類する」「正式な議事録に整える」と工程を分けると、不具合が出た部分を調整しやすい。ただし、短い要約だけなら一つのスキルで足りることもある。分割そのものを目的にせず、修正・確認のしやすさで考えたい。

指示で直せる問題と、必要な機能がない問題は分けて扱う。非対応の機能、読み込めない形式、接続権限の不足は、指示を書き足すだけでは解決しない。別の道具で処理して結果を渡すなど、工程全体を見直して試す必要がある。

これまで蓄積した指示や資料、良い出力の見本は、サービスが変わっても仕事を引き継ぐ手掛かりになる。業務の自動化を進める前に、何を引き継ぎ、何を確かめるかを整理しておきたい。
